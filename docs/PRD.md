# FlowCAD PRD — 수문 제조 설계 자동화

2026-10-01 · v2.2 (v1의 건축 매스 모델러 내용은 잘못 들어간 것이어서 전면 교체. v2.1: ANY 규칙 스펙 v0 반영. v2.2: 3D 뷰어를 핵심 기능(P0)으로 올림)

## 1. 제품 개요

FlowCAD는 수문 규격(형식·크기·구동 방식·연동 수·수량)을 입력하면, 협업 제조사의 설계 규칙에 따라
**제작 도면, 부품표(BOM), 절단 목록(Cut List), 판재 네스팅, 발주서**를 몇 초 안에 만들어 주는 웹 도구다.

- **문제**: 수문 제작 도면은 규격이 조금만 달라도 설계자가 기존 도면을 손으로 고쳐 다시 그리고, 부품·자재 수량을 다시 산출한다. 한 건에 수 시간에서 수십 시간이 걸리고, 산출 실수가 자재 낭비와 재작업으로 이어진다.
- **해결**: 업체의 실제 제작 도면(DWG 약 34장: FRP·일체식·롤러게이트·인양식)에서 뽑은 설계 규칙을 **규칙 엔진**으로 만들고, 입력값에서 도면과 산출물을 자동으로 만든다.
- **핵심 경험**: 자재 규격(형식·W·H·련 수·판 두께 등)을 바꾸면 **웹 화면 안의 3D CAD 뷰에서 수문 형상이 즉시 다시 그려져** 눈으로 확인할 수 있다. 2D 도면·BOM은 같은 설계 모델에서 함께 갱신된다.
- **AI의 역할(단계적)**: MVP는 결정적(deterministic) 규칙 엔진이다. AI는 ① 도면·계산서에서 규칙을 추출해 규칙 엔진에 넣는 작업을 돕고(ARC 팀 ANY), ② 이후 업체 도면 데이터가 쌓이면 규칙에 없는 규격을 보간·검증하는 데 쓴다. "AI가 도면을 직접 그린다"는 MVP 범위가 아니다.
- **차별점**: 일반 CAD·파라메트릭 도구가 아니라, 수문 형식별 **제작 규칙과 자재 산출까지 한 번에** 처리한다.

## 2. 사용자와 시나리오

| 사용자 | 상황 | FlowCAD로 하는 일 |
| --- | --- | --- |
| 협업 제조사 설계 담당 | 견적·수주 직후 제작 도면 작성 | 규격 입력 → 도면(DXF)·Cut List 내려받아 검토·보정 |
| 제조사 영업·견적 담당 | 발주처 문의 대응 | 규격만 넣고 자재비·중량·납기를 바로 안내 |
| 구매 담당 | 자재 발주 | 공급사별로 묶인 발주서와 판재 매수 확인 |

**대표 시나리오**: 롤러게이트, 련당 W 3500 × H 4000, 3련, 수량 1을 입력한다. 정면도·측면도가 담긴 DXF,
BOM(현재 데모 9종 — 측면 주형·권양 축 등 빠진 부재는 업체 확인 후 추가), SS400 판재 절단 목록과 표준 시트 매수·로스율,
공급사별 발주서가 함께 나온다.
설계자는 DXF를 CAD에서 열어 업체 도면 양식대로 마무리한다.

## 5. MVP 범위

**포함**

- 3장의 5개 형식에 대한 규칙 엔진과 기준 테스트
- 입력 → 도면 미리보기 → DXF·BOM·Cut List(네스팅 포함)
- 단가는 데모 표준값이며, 화면에 "추정" 표시

**제외(이후 단계)**

- 로그인·클라우드 저장, 업체 ERP 연동
- 구조 계산 자동 검토(설계기준 KDS 적합성 판정). MVP는 규칙상 필요한 값만 산출하고 적합성은 사람이 확인한다
- 실제 부재 형상 네스팅(곡선·자유형), DWG 직접 출력
- AI 기반 규격 보간

## 6. 기술 아키텍처

서버 없이 브라우저만으로 동작한다. 계산량이 작아(부품 수십 개) Web Worker나 WASM 지오메트리 커널은 MVP에 쓰지 않는다.

```
입력 폼 ──► 규칙 엔진(engine/) ──► 설계 모델(JSON: 부재 목록 + 2D 형상)
                                      ├─► 3D 뷰어(Three.js)
                                      ├─► SVG 미리보기
                                      ├─► DXF 생성기
                                      ├─► BOM / Cut List / 네스팅
                                      └─► 발주서(xlsx)
```

| 계층 | 선택 | 이유 |
| --- | --- | --- |
| 프런트엔드 | React + TypeScript + Vite | 데모(React+Vite)를 이어받음, 규칙 엔진에 타입 필요 |
| 3D 뷰어 | Three.js + React Three Fiber(+ drei) | WebGL 표준, React와 상태 공유 쉬움. 부재가 판·형강·원기둥 수십 개라 불리언 커널 불필요 |
| 규칙 엔진 | 순수 TypeScript 모듈(`src/engine/`) | UI와 분리해 테스트·재사용(이후 서버·SDK에서도 그대로 사용) |
| DXF | 직접 작성 또는 경량 라이브러리(도입 시 이유 기록) | R12/2000 호환 ASCII DXF |
| 테스트 | Vitest | 규칙 엔진 기준 테스트(fixtures) |
| 배포 | 정적 호스팅(Vercel) | 데모와 같은 방식 |

**설계 모델이 단일 원천이다**: BOM·Cut List·도면은 모두 규칙 엔진이 만든 같은 부재 목록에서 나온다.
데모는 BOM과 도면이 각자 개수식을 따로 갖고 있어 거더·롤러·권양기 수가 서로 다르다(7장 9번). 도면 형상도 픽셀이 아니라 mm로 정의한다.

**데이터 규칙**

- 단위는 mm, 무게는 kg, 금액은 원. 좌표는 도면 기준 X(폭)·Y(높이)
- 설계 모델·프로젝트 파일에는 `schemaVersion`을 넣는다. 버전을 올릴 때는 이전 버전 변환 함수를 함께 만든다
- 모든 규칙 상수(여유 300mm, SEAL PLATE Ø(D−10) 등)는 한곳(`src/engine/rules/`)에 모으고, 출처 도면 번호를 주석으로 단다

## 7. 데모 코드에서 고칠 점(이관 시 반영)

`flowcad-demo/src/FlowCADDemo.jsx`의 규칙 엔진을 옮길 때 아래를 고친다.

1. **표준 시트보다 큰 판재가 "시트 1매"로 계산된다.** 예: SKIN PLATE 3000×4000은 SS400 시트(1524×3048)에 들어가지 않는데, `Math.max(1, …)` 때문에 1매로 잡혀 로스율이 0%가 된다. 이음(splice) 규칙을 적용하거나 "시트 초과" 경고를 내야 한다
2. **원형 FRP SEAL PLATE를 둘레 길이의 띠판으로 절단하는 것으로 계산한다.** 실제 제작 방식(원판 가공인지 분할 띠판인지)을 도면에서 확인해야 한다
3. **설치 여유 300mm(`RULE_CLEARANCE`)가 화면에만 표시되고 계산에는 쓰이지 않는다**
4. **"설계+산출 시간 절감" 지표(`existH`·`saveRate`)는 근거 없는 추정식이다.** 실측값으로 바꾸기 전에는 "추정" 표시를 하거나 제외한다
5. **쓰이지 않는 계산이 있다.** `steelKg`, `nest.plateKg * 0`, `.length * 0`은 삭제한다
6. **입력 검증이 없다.** 빈칸이면 형식마다 다른 기본값(`|| 800`, `|| 3000`)으로 조용히 바뀐다. 허용 범위를 명시하고 오류를 표시한다
7. **문비·SEAL PLATE 단가가 0원이라 BOM 합계에 빠진다.** 판재 kg 단가로 Cut List 쪽에서만 계산되므로, 어느 쪽에서 합산하는지 명확히 한다
8. **비용이 이중 계상되거나 누락된다.** 롤러 보강거더·FRP 사각 LINK/CLAMP는 BOM 단가와 절단 kg 단가 양쪽에 잡히고, 일체식·인양식 GUIDE FRAME은 어디에도 잡히지 않는다. 발주서는 단가 > 0인 줄만 담아 판재 구매가 빠진다(11장 결정 1)
9. **BOM과 도면의 개수식이 다르다.** 롤러 거더(BOM max(3,H/600) vs 도면 max(2,H/600)−1), 롤러 수, 권양기(BOM 련마다 1대 vs 도면 1대), 보강재 피치(H/250·H/700 vs 도면 H/600). 6장 단일 원천 구조로 해결
10. **원형 SEAL PLATE가 BOM(1.5T Ø(D−10) 원판)과 절단(5T 190×πD 띠판)에서 다르다.** 중량이 약 3.7배 차이. 업체 확인 전까지 절단 쪽 값을 유지하고 경고 표시
11. **스펙 불일치**: 일체식 전동은 액추에이터 "스핀들 Ø38"인데 SPINDLE은 Ø32 고정, 스핀들 커버 중량 계수가 이론값의 약 3배

전체 목록(25건)과 근거 줄번호는 ANY 규칙 스펙 v0(`llm-wiki/01 프로젝트/Flowcad 규칙 스펙 v0.md`, 비공개 볼트)에 있다.

## 8. 비기능 요구사항

| 항목 | 목표 |
| --- | --- |
| 입력 → 결과·3D 갱신 | 100ms 이하(일반 노트북) |
| 3D 뷰 조작 | 60fps(롤러게이트 5련 기준, 내장 그래픽) |
| 정확도 | 기준 도면 세트에서 부재 종류 100% 일치, 주요 치수 오차 0mm(규칙 적용 대상) |
| 브라우저 | Chrome·Edge 최신 2개 버전 |
| DXF | AutoCAD·ZWCAD에서 열리고 레이어가 분리되어 있을 것 |
| 보안 | 업체 실제 도면·단가는 저장소에 커밋하지 않는다(`data/private/`는 git 제외) |

## 9. 개발 로드맵

통과 조건을 충족하지 못하면 다음 단계로 넘어가지 않는다.

| 단계 | 내용 | 통과 조건 |
| --- | --- | --- |
| 0. 이관 | 데모를 TS 프로젝트(`app/`)로 옮기고 규칙 엔진을 UI에서 분리, 7장 1·3·5·6 수정 | 기존 데모와 같은 입력에서 같은 BOM(수정 항목 제외), 테스트 통과 |
| 1. 규칙 스펙화 | ANY가 데모·업체 도면에서 규칙 스펙 작성, RESIR가 외부 기준 정리, 규칙에 출처 기록 | 5개 형식 규칙 스펙 + 빈틈·모순 목록 확정(개발자 확인) |
| 2. 3D 뷰어 | 설계 모델(부재 목록 + mm 형상) 정의 → Three.js 3D 표시, BOM·2D 도면도 같은 모델에서 생성 | 5개 형식 모두 3D 표시, 입력 변경 시 즉시 갱신, 3D 부재 수 = BOM 수량(테스트) |
| 3. 도면 생성 | 설계 모델 → SVG·DXF(정면·측면, 레이어, 표제란) | CAD에서 열림, 기준 도면 3장과 주요 치수 일치 |
| 4. 산출물 정밀화 | 네스팅 개선(이음 규칙), 단가 DB 분리, 발주서 xlsx | 업체 견적서 1건과 자재 수량 일치 |
| 5. 현장 검증 | 협업 제조사 설계 담당자가 실제 건 3개를 FlowCAD로 처리 | 수정 시간이 기존 대비 절반 이하(실측) |

## 10. 성공 지표와 리스크

**지표**

- 실제 건 기준 도면 작성 시간(실측, 기존 대비)
- 설계자가 DXF를 받은 뒤 고친 부재 수(적을수록 좋음)
- BOM 자재 수량과 실제 발주 수량의 차이

**리스크**

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 업체 규칙이 문서화되어 있지 않고 설계자 경험에 있음 | 규칙 빈틈 | ANY가 빈틈 목록을 만들고 업체 인터뷰로 채움 |
| 기준 도면이 34장뿐이라 일부 규격 범위를 덮지 못함 | 보간 오류 | 범위 밖 입력은 "규칙 미검증" 경고 |
| 설계기준(KDS) 적합성 오해 | 안전 책임 | MVP 산출물에 "구조 검토 별도" 명시 |
| 도면·단가 유출 | 업체 신뢰 상실 | 비공개 데이터는 저장소 밖 보관, 공개 저장소에는 데모 표준값만 |
| 공동 작업 저장소 충돌 | 작업 손실 | `prototype` 브랜치에서 실험 → 확인 후 `main` PR |
